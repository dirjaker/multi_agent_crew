# Multi-Agent Crew 协作系统 — 技术设计文档

> 项目定位：一个多智能体协作框架，支持顺序/并行/层级三种执行模式，让 AI Agent 组成团队协作完成复杂任务。

---

## 第一章 项目背景与价值

### 为什么做

单个 AI Agent 在处理复杂任务时存在明显局限：

1. **上下文窗口限制**：单个 Agent 难以同时处理收集、分析、写作等多个环节
2. **角色混淆**：让一个 Agent 扮演多个角色会导致输出质量下降
3. **无法并行**：独立子任务无法同时执行，效率低
4. **缺乏协作机制**：没有标准化的 Agent 间通信和任务编排方案

Multi-Agent（多智能体）是当前 AI Agent 领域的核心范式之一，CrewAI、AutoGen 等框架验证了市场价值。本项目从零实现了一个轻量级多智能体协作框架，涵盖 Agent 定义、任务编排、执行引擎、记忆系统和工具注册等核心能力。

### 面试话术

> "我实现了一个多智能体协作框架，核心是让多个 AI Agent 组成团队按不同模式协作完成任务。支持三种执行模式：顺序执行（任务链）、并行执行（ThreadPoolExecutor）、层级管理（Manager-Worker）。每个 Agent 有角色、目标、背景故事，采用 ReAct 模式（推理+行动）执行任务。技术上用 dataclass 做数据建模，ThreadPoolExecutor 做并行调度，DAG 管理任务依赖，记忆系统分短期/长期两层。框架设计为可插拔的——工具系统支持自定义扩展，LLM 后端可替换。此外还提供了 FastAPI Web API 和 tkinter 桌面 GUI 两种交互方式。"

**三种协作模式流程：**

```
Sequential（顺序执行）:
  Agent1(Task1) → Output1 → Agent2(Task2) → Output2 → Agent3(Task3) → Final

Parallel（并行执行）:
  Agent1(Task1) ─┐
  Agent2(Task2) ─┼→ ThreadPoolExecutor → Aggregate → Final
  Agent3(Task3) ─┘

Hierarchical（层级管理）:
  Manager
  ├── Assign Task1 → Worker1 → Result1
  ├── Assign Task2 → Worker2 → Result2
  └── Assign Task3 → Worker3 → Result3
      ↓
  Manager: 汇总 → Final
```

### 3.1 Agent 智能体模块 — `agent.py`

**核心数据结构：**

```python
class AgentState(Enum):
    IDLE = "idle"
    WORKING = "working"
    WAITING = "waiting"
    COMPLETED = "completed"
    ERROR = "error"

@dataclass
class AgentMemory:
    short_term: List[Dict[str, Any]]   # 短期记忆（当前任务上下文）
    long_term: List[Dict[str, Any]]    # 长期记忆（历史经验）
    max_short_term: int = 10            # 短期记忆容量

@dataclass
class Agent:
    id: str                     # UUID 前8位
    role: str                   # 角色名称（如"研究员"）
    goal: str                   # 目标描述
    backstory: str              # 背景故事（注入 LLM prompt）
    tools: List[Tool]           # 可用工具列表
    memory: AgentMemory         # 记忆系统
    state: AgentState           # 状态机
    max_iter: int = 5           # 最大迭代次数
    llm_config: Dict            # LLM 配置（model/temperature/max_tokens）
```

**核心方法 — ReAct 模式执行：**

```python
def act(self, task: str) -> str:
    """ReAct 模式：Reasoning + Acting"""
    self.state = AgentState.WORKING

    # 1. 推理（Reasoning）
    thought = self.think(task)

    # 2. 行动（Acting）
    if self.tools:
        tool = self.tools[0]
        action_result = self.use_tool(tool.name, task=task)
        result = f"思考：{thought}\n行动：使用 {tool.name}\n结果：{action_result}"
    else:
        result = f"思考：{thought}\n行动：直接回答\n结果：基于我的知识，{task}"

    self.state = AgentState.COMPLETED
    return result
```

**系统提示词生成：**

```python
def get_system_prompt(self) -> str:
    tools_desc = ""
    if self.tools:
        tools_desc = "\n可用工具：\n"
        for tool in self.tools:
            tools_desc += f"- {tool.name}: {tool.description}\n"
    return f"""你是一个名为 {self.role} 的 AI 智能体。

目标：{self.goal}

背景：{self.backstory}

{tools_desc}

请根据你的角色和目标，完成分配给你的任务。"""
```

**记忆系统：**

```python
def add_short_term(self, content: str, metadata: Dict = None):
    """短期记忆 — 滑动窗口，超出容量移除最旧"""
    memory = {"id": uuid4()[:8], "content": content, "metadata": metadata}
    self.short_term.append(memory)
    if len(self.short_term) > self.max_short_term:
        self.short_term.pop(0)

def add_long_term(self, content: str, importance: float = 0.5):
    """长期记忆 — 持久化存储，带重要性评分"""
    memory = {"id": uuid4()[:8], "content": content, "importance": importance}
    self.long_term.append(memory)

def get_context(self, limit: int = 5) -> str:
    """获取最近 N 条短期记忆作为上下文"""
    recent = self.short_term[-limit:]
    return "\n".join([m["content"] for m in recent])
```

**工厂函数：**

```python
def create_agent(role: str, goal: str, backstory: str,
```

### 3.2 Task 任务模块 — `task.py`

**核心数据结构：**

```python
class TaskStatus(Enum):
    PENDING = "pending"
    IN_PROGRESS = "in_progress"
    COMPLETED = "completed"
    FAILED = "failed"
    BLOCKED = "blocked"

@dataclass
class Task:
    id: str
    description: str
    expected_output: str
    agent: Agent
    priority: TaskPriority         # LOW / MEDIUM / HIGH / URGENT
    dependencies: List[str]        # 依赖的任务 ID 列表（DAG）
    status: TaskStatus
    max_retries: int = 3
    retry_count: int = 0
```

**依赖检查（DAG 支持）：**

```python
def is_ready(self, completed_tasks: List[str]) -> bool:
    """检查所有依赖是否已完成"""
    if self.status != TaskStatus.PENDING:
        return False
    return all(dep in completed_tasks for dep in self.dependencies)
```

**任务执行流程：**

```python
def execute(self, context: str = "") -> TaskResult:
    self.status = TaskStatus.IN_PROGRESS
    start_time = time.time()

    try:
        # 构建完整描述：前序任务输出 + 当前任务描述 + 参考信息
        full_description = self.description
        if context:
            full_description = f"{context}\n\n任务：{self.description}"
        if self.context:
            full_description += f"\n\n参考信息：\n" + "\n".join(self.context)

        # 委托给 Agent 执行
        output = self.agent.act(full_description)

        self.result = TaskResult(
            task_id=self.id, status=TaskStatus.COMPLETED,
            output=output, duration=time.time() - start_time
        )
    except Exception as e:
        self.result = TaskResult(
            task_id=self.id, status=TaskStatus.FAILED,
            error=str(e), duration=time.time() - start_time
        )
    return self.result
```

### 3.3 Crew 协作引擎 — `crew.py`

**核心数据结构：**

```python
class ProcessType(Enum):
    SEQUENTIAL = "sequential"
    PARALLEL = "parallel"
    HIERARCHICAL = "hierarchical"

@dataclass
class Crew:
    name: str
    agents: List[Agent]
    tasks: List[Task]
    process: ProcessType
    max_workers: int = 4        # 并行执行的线程数
```

**执行分发（策略模式）：**

```python
def kickoff(self) -> CrewResult:
    start_time = time.time()
    if self.process == ProcessType.SEQUENTIAL:
        result = self._execute_sequential()
    elif self.process == ProcessType.PARALLEL:
        result = self._execute_parallel()
    elif self.process == ProcessType.HIERARCHICAL:
        result = self._execute_hierarchical()
    result.total_duration = time.time() - start_time
    return result
```

**顺序执行（上下文传递）：**

```python
def _execute_sequential(self) -> CrewResult:
    results = []
    context = ""
    for task in self.tasks:
        # 检查依赖
        completed_ids = [r.task_id for r in results if r.is_success()]
        if not task.is_ready(completed_ids):
            result = TaskResult(task_id=task.id, status=TaskStatus.BLOCKED,
                                error=f"依赖未完成: {task.dependencies}")
        else:
            result = task.execute(context)
        results.append(result)
        # 前序输出作为后续上下文
        if result.is_success():
            context = str(result.output)
    return CrewResult(...)
```

**并行执行（ThreadPoolExecutor）：**

```python
def _execute_parallel(self) -> CrewResult:
    results = []
    with ThreadPoolExecutor(max_workers=self.max_workers) as executor:
        future_to_task = {}
        for task in self.tasks:
            future = executor.submit(task.execute, "")
            future_to_task[future] = task
        for future in as_completed(future_to_task):
            task = future_to_task[future]
            try:
                results.append(future.result())
            except Exception as e:
                results.append(TaskResult(task_id=task.id,
                    status=TaskStatus.FAILED, error=str(e)))
    # 聚合所有成功结果
    final_output = "\n---\n".join([str(r.output) for r in results if r.is_success()])
    return CrewResult(...)
```

**层级执行（Manager-Worker）：**

```python
def _execute_hierarchical(self) -> CrewResult:
    manager = self.agents[0]       # 第一个 Agent 作为 Manager
    workers = self.agents[1:]      # 其余为 Worker
    results = []
    for i, task in enumerate(self.tasks):
        worker = workers[i % len(workers)]  # 轮询分配
        task.agent = worker
        result = task.execute()
        results.append(result)
    # Manager 汇总
    summary = "\n".join([f"- {r.output}" for r in results if r.is_success()])
    final_output = f"任务汇总 ({success}/{len(results)} 成功):\n{summary}"
    return CrewResult(...)
```

**安全沙箱：**

## 第四章 技术亮点

### 4.1 三种执行模式的策略模式设计

`kickoff()` 方法根据 `ProcessType` 分发到不同的执行策略（`_execute_sequential` / `_execute_parallel` / `_execute_hierarchical`），是经典的策略模式。新增执行模式只需添加新的 `_execute_*` 方法。

### 4.2 DAG 任务依赖管理

`Task.dependencies` 支持任务间依赖关系，`is_ready()` 方法检查所有前置任务是否完成。Sequential 模式下自动传递前序输出作为后续上下文。支持 BLOCKED 状态处理依赖未满足的情况。

### 4.3 并行执行的线程池调度

使用 `concurrent.futures.ThreadPoolExecutor` + `as_completed` 实现并行任务调度：
- `max_workers` 可配置并发数
- `as_completed` 按完成顺序收集结果，而非提交顺序
- 异常隔离：单个任务失败不影响其他任务

### 4.4 ReAct 模式的 Agent 执行范式

Agent 的 `act()` 方法实现 Reasoning + Acting 范式：
1. **Think** — 推理当前任务（生成思考链）
2. **Act** — 选择并调用工具
3. **Observe** — 将结果存入记忆

这个模式是当前主流 Agent 框架（LangChain、CrewAI）的核心范式。

### 4.5 分层记忆系统

- **短期记忆**：滑动窗口（最多 10 条），用于当前任务上下文
- **长期记忆**：无限容量，带重要性评分，可持久化
- `get_context(limit=5)` 方法返回最近记忆的文本摘要，可直接注入 prompt

### 4.6 可插拔的工具系统

Tool 基类通过组合模式实现——每个 Tool 是一个 `name + description + function` 的封装。Agent 的 `use_tool()` 方法按名称查找工具并执行，结果自动存入短期记忆。支持通过继承 Tool 类或直接传入 callable 扩展。

### 4.7 安全沙箱机制

`safe_eval()` 和 `safe_exec()` 通过 AST 解析 + 危险模式黑名单 + 内置函数白名单三重保护，防止工具执行时的代码注入攻击。

## 第五章 面试常见问题

**Q1: 三种执行模式分别适合什么场景？**

> Sequential 适合有依赖关系的任务链（如：研究员收集→分析师分析→作家撰写），前序输出自动传递给后续任务作为上下文。Parallel 适合独立任务（如：三个写手并行写不同章节），用 ThreadPoolExecutor 并发执行。Hierarchical 适合需要协调的场景（如：Tech Lead 分配任务→开发执行→Lead 汇总），第一个 Agent 自动成为 Manager。

**Q2: 任务依赖是怎么实现的？**

> 每个 Task 有一个 `dependencies: List[str]` 字段存储依赖的任务 ID。执行前调用 `is_ready(completed_tasks)` 检查所有依赖是否已完成。Sequential 模式下，前序任务的输出会作为 `context` 参数传递给后续任务的 `execute()` 方法。

**Q3: 并行执行怎么保证线程安全？**

> 用 `concurrent.futures.ThreadPoolExecutor` 管理线程池。每个 Task 的 `execute()` 是独立的——虽然 Agent 的 memory 是共享的，但当前实现中并行任务不传递上下文（传空字符串），所以不存在竞态。如果要支持并行任务共享状态，可以加锁或用队列。

**Q4: Agent 的 ReAct 模式具体是怎么工作的？**

> `act()` 方法分两步：先调用 `think()` 生成推理过程（当前是模拟，实际项目会调 LLM API），再调用 `use_tool()` 执行行动。思考和行动的结果都会存入短期记忆。这样 Agent 的决策过程是可追溯的——每一步的"想了什么、做了什么、结果是什么"都有记录。

**Q5: 记忆系统的设计考量是什么？**

> 分短期和长期两层。短期记忆用滑动窗口（最多 10 条），用于当前任务的上下文累积——超过容量自动淘汰最旧的。长期记忆无容量限制，带重要性评分，用于跨任务的经验积累。`get_context()` 取最近 N 条短期记忆拼成文本，可以直接注入 LLM 的 prompt。

**Q6: 如果要接入真实的 LLM，需要改哪些地方？**

> 主要改 Agent 的 `think()` 方法——当前是字符串拼接模拟，替换为调用 LLM API（如 OpenAI/DeepSeek）。需要把 `get_system_prompt()` 的输出作为 system message，记忆上下文作为 user message。工具调用部分需要实现 function calling 协议。整体改动集中在 agent.py 一个文件。

**Q7: 和 CrewAI 这类成熟框架相比，你的项目有什么异同？**

> 核心设计思想相同：Agent + Task + Crew 三层抽象，支持多种执行模式。区别在于：1) CrewAI 有完整的 LLM 集成和 function calling，我的是框架层设计，LLM 层预留了接口；2) 我的并行执行用的是 ThreadPoolExecutor，CrewAI 用的异步；3) 我的工具系统更轻量，CrewAI 有更丰富的内置工具和第三方集成。

**Q8: Hierarchical 模式中 Manager 是怎么分配任务的？**

> 当前实现是轮询分配（round-robin）：`worker = workers[i % len(workers)]`。这是简化版，实际项目中 Manager 应该先分析任务复杂度和 Worker 的能力，再做智能分配。改进方向是让 Manager 调用 LLM 做任务拆解和分配决策。
